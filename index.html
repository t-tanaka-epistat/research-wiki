VS Code + Quarto + R 研究環境構築完全マニュアル

博士課程学生のための再現性ある文献検索・文献管理・研究計画・解析・執筆環境の構築（GitHub Copilot / セキュリティ対策）

Published

December 26, 2025

1 Introduction: 哲学と目的

本ドキュメントは、医学・疫学分野の博士課程において、「再現性 (Reproducibility)」「効率性 (Efficiency)」「拡張性 (Scalability)」を最大化するために構築された研究エコシステムの仕様書である。

従来のツール (R, Git) に現代的なAI (LLM) を有機的に統合し、文献探索から論文執筆までのプロセスを「工場（Factory）」のようにシステム化することを目的とする。

1.1 Core Philosophy

  1. Single Source of Truth: データと解析コードこそが正義であり、Word上の手入力数値は信じない。
  2. AI Synergy: AIは「思考の壁打ち相手」かつ「単純作業の自動化担当」として徹底活用する。
  3. Reproducibility: 3年後の自分、あるいは未来の後輩が、エンターキー1つで全く同じ図表を再現できるようにする。

2 Architecture: 全体像とツール群

本エコシステムは、情報の流れに合わせて4つのレイヤーで構成される。

2.1 Layer 1: The Radar (探索・俯瞰)

  • 広大な海からリサーチクエスチョン (RQ) に合致するエビデンスを探知する。
    • Consensus / Elicit: RQに基づくAI文献検索。
    • Mapify: 概念のマインドマップ化。

2.2 Layer 2: The Filter (収集・選別)

  • 情報のノイズを除去し、精読すべきものを管理する。
    • Paperpile: 引用管理・PDF書庫（iPad連携）。
    • NotebookLM: 大量のPDFを読み込ませたAI要約・トリアージ。

2.3 Layer 3: The Brain (思考・管理)

  • プロジェクトの進行、アイディアのバージョン管理、知識の蓄積。
    • Notion: プロジェクトハブ、タスク管理、統計Wiki。
    • ChatGPT / Gemini: 壁打ち、コード生成、Notionへの自動記録。
    • Zapier: AIとNotionをつなぐコネクタ。

2.4 Layer 4: The Factory (実装・執筆)

  • 最終的な成果物（論文・解析結果）を生産する。
    • VSCode: 統合開発環境 (IDE)。
    • Quarto (R): 解析と執筆の統合プラットフォーム。
    • Git / GitHub: 変更履歴の管理。

    • Research Question: …
    • GitHub Repo: Link

Ideation & Draft Logs (思考の履歴) Geminiとの壁打ち結果をここに時系列で保存する

  • ▶ 2025-XX-XX: Ver 0.2 - With PS Matching (トグル)

    • プロンプト: “交絡調整のためにPSマッチングを追加したプロトコルに修正して”

    • 出力結果: (以下のコードブロック)

      %%| label: Gemini出力イメージ
# Study Protocol Draft v0.2
## Study Design
...

  • ▶ 2025-XX-XX: Ver 1.0 - FIX for Coding (トグル) これ以降はVSCode/Gitへ移行

運用ルール: “Code Block” Strategy NotionにMarkdownを貼り付ける際は、必ず「コードブロック」を使用すること。

  1. Geminiで出力: アイディアや構成案をMarkdown形式で出力させる。
  2. Copy: 出力されたMarkdownをコピーする。
  3. Paste to Notion:
    • Notion上で /code と入力し、コードブロックを作成。
    • 言語を Markdown に設定。
    • その中にペーストする。
Noteなぜコードブロックなのか？

Notionの通常テキストとして貼り付けると、勝手に整形（リスト化や太字化）され、VSCode (.qmd) に戻す際にフォーマット崩れや不要な改行が発生するため。「純粋なテキストデータ」として保存・運搬するためにコードブロックが最適である。

5 AI Search & Visualization: エビデンス探索の実装

「気まぐれな検索」を廃止し、Consensus / Elicit / Mapify を用いた体系的なエビデンス収集フローを定義する。 これらのツールで得られた知見は、ブラウザのタブで終わらせず、必ず Notion に資産として蓄積する。

5.1 Consensus & Elicit (AI Search)

従来のようなキーワード検索ではなく、「リサーチクエスチョン (RQ)」を直接問いかける。

5.1.1 使い分け

  • Consensus: 「Yes/No」で答えられる疑問や、一般的な科学的合意を知りたい時。
    • Prompt例: “Does statin use increase the risk of diabetes in elderly patients?”
  • Elicit: 特定のトピックについて、複数の論文から表形式（Matrix）で詳細を抽出したい時。
    • Prompt例: “Find papers regarding TTE implementation in oncology PMS data.”

5.1.2 出力結果の保管 (Notion Workflow)

検索結果を流してしまわないために、Notionに “Evidence Search Log” データベースを作成し、以下のルールで記録する。

DBプロパティ構成案:

プロパティ名 種類 用途
Query / Topic Title 検索した質問文 (RQ)
AI Tool Select Consensus, Elicit, Perplexity
Synthesis Text AIが出力した「まとめ（Synthesize）」 をコピペする。
Result URL URL 検索結果ページ自体の共有リンク。
Key Papers Text 特に重要だった論文のタイトル（Paperpileへ登録済みのもの）。
Related Study Relation Study Portfolio DB と紐付け。
NoteElicitの活用テクニック

Elicitで作成した論文リスト（Table）は .bib 形式でエクスポートできる。これをPaperpileにインポートすれば、検索から文献管理への移行がシームレスに完了する。

5.2 Mapify (Visualization)

複雑な概念や、Consensus/Elicitで得られた大量の情報を「一枚の地図（マインドマップ）」に変換し、直感的な理解を促す。

5.2.1 使用シーン

  • 新規領域の全体像把握: “Overview of Causal Inference methods in epidemiology” などをマップ化。
  • 長文PDFの構造化: 難解なプロトコルやガイドラインをアップロードし、要点を可視化する。

5.2.2 出力結果の保管

Mapifyの出力は動的であるため、以下の2通りの方法で Notion の Study Portfolio (各研究ページ) の「Ideation & Draft Logs」セクションに保存する。

  1. Embed (埋め込み): Mapifyの共有リンクを発行し、Notionに /embed で埋め込む（操作可能な状態で保存）。
  2. Image: 画像 (.png) としてエクスポートし、Notionに貼り付ける（視認性重視）。

6 Paperpile × Notion: 究極の文献管理

「積読」を防ぎ、iPadでの快適な読書を実現するためのハイブリッド運用。

ラベル管理ルール (Paperpile) Paperpileのフォルダではなく「ラベル」を活用し、ステータスを可視化する。 記号を接頭辞にすることで、ソート順を固定する。

  • Status (フロー)
    • ! To Read: Inboxから移動した「未読」論文。iPadでまずここを開く。
    • > Reading: 現在進行系で読んでいる・iPadで開きっぱなしのもの。
    • ✔ Annotated: 読了し、ハイライトやメモを残したもの（完了）。
  • Priority (重要度)
    • ★ Key Paper: 研究の根幹に関わる重要論文。
    • Review: 総説。
    • Methodology: 統計手法や実装コードの参考にする論文。
  • Context (文脈)
    • @PhD: 博士論文用。
    • @Work: 企業業務・PMS用。
  • 連携フロー
    • PC: Chrome拡張機能でPaperpileに保存し、即座にラベル(! To Read 等)を付ける。PCで読む際は、Paperpileのリーダーを「google drive」にすると、Geminiがサイドパネルで要約を表示してくれる。
    • iPad: Paperpileアプリで ! To Read ラベルを開き、読む。書き込む。
    • PC: 読み終わった重要論文は、Notionの「Literature Matrix」にリンクを貼り、要約を残す。
      • NotebookLMにPDFをアップロードし、要約やインフォグラフィックスを生成させ、Paperpile内に保存するのも有効。（参考：NotebookLM活用例）

7 ChatGPT × Notion: 「俺の統計Wiki」構築

AIとの壁打ち結果を、コピペの手間なくデータベース化する。

  • 仕組み : ChatGPT (Custom GPTs) から Zapier AI Actions を経由してNotion APIを叩く。
  • 運用:
    1. 統計用語やモデルについてChatGPTと壁打ちする。
    2. 「これをWikiに保存して」と指示する。
    3. 自動的にNotionの Stats Knowledge Base に「用語」「数式(LaTeX)」「解説」が構造化されて保存される。
    4. Notionのトグル機能等を使い、後でクイズとして復習する。

7.1 導入方法

  1. Zapierアカウントを作成し、NotionとChatGPTを連携する。
  2. 新しいZapを作成し、Triggerを「AI Action: ChatGPT」、Actionを「Notion: Create Database Item」に設定する。
  3. NotionのStats Knowledge Baseデータベースのプロパティに合わせて、Zapierのフィールドをマッピングする。
  4. ChatGPTで壁打ち中に「この内容をWikiに保存して」と指示すれば、自動的にZapが発動し、Notionに保存される。

8 VSCode × Quarto: 再現性のある解析環境

長年 R ユーザーに愛されてきた RStudio から、Visual Studio Code (VS Code) へ移行する研究者が増えている。本マニュアルは、その環境構築手順と、研究データのセキュリティを守るための運用ルールをまとめたものである。WordやExcelを使わず、すべてをテキストベースで管理する。

8.1 ディレクトリ構成 (Standard Layout)

Mono-repository構成を採用し、データとコードを厳格に分離する。

PhD_Project_Root/
├── .gitignore          # 必須：データを除外設定
├── _quarto.yml         # プロジェクト全体設定
├── data/               # データ置き場 (Git管理外)
│   ├── raw/            # 【絶対変更禁止】 生データ (Read Only)
│   └── processed/      # Rで加工したデータ (.rds / .csv)
├── R/                  # 汎用関数 (theme_publication.R など)
├── studies/            # 研究ごとの作業フォルダ
│   ├── study1_baseline/
│   │   ├── 01_protocol.qmd  # 計画書 (Notionから移植)
│   │   ├── 02_analysis.qmd  # 解析コード
│   │   └── 03_paper.qmd     # 論文原稿
│   └── study2_longitudinal/
├── output/             # 生成物
│   ├── figures/        # 論文用図表
│    └── reports/        # レンダリングされたHTML/PDF
└── manuals/            # マニュアル類
    └── VSCode_Quarto_R_Setup.qmd  # 本マニュアル

8.2 VS Code を推奨する3つの理由

  1. AI支援（GitHub Copilot）との統合が最強
    • エラーの原因特定、コード自動生成、数式の LaTeX 化まで、強力な AI が「副操縦士」としてサポートしてくれる。
  2. Quarto のプレビュー速度と柔軟性
    • RStudio より高速で、Markdown、Mermaid（作図）、Rコード、プレビュー画面を自由に配置できる。
  3. 多言語対応
    • 将来的に Python や Shell Script を使う際も、同じエディタで完結する。

8.3 デメリットとピットフォール（共有時の注意点）

VS Code は強力だが、以下の点に注意が必要である。

  • 初期設定の壁: RStudio ならインストールするだけで動くが、VS Code は「拡張機能」や「パス設定」が必要。本マニュアルの手順を遵守すること。
  • PDF出力の日本語フォント: PDF化する際、日本語が表示されないトラブルが起きやすい（後述の TinyTeX 設定で対応）。
  • 【最重要】データ漏洩リスク: GitHub 連携が簡単なため、「患者データ（PMSデータ等）を誤ってアップロードしてしまう」リスクがある。これを防ぐ .gitignore 設定は必須である（第5章参照）。

8.4 基礎環境のインストール (R & Rtools)

統計解析のエンジンとなる R 言語環境を構築する。

8.4.1 R 本体

  1. CRAN から最新のインストーラーをダウンロード・実行する。

8.4.2 Rtools（最重要）

Windows でパッケージをソースからビルドするために必須。これがないとパッケージが入らないことがある。

  1. Rtools Download から、R のバージョンに合うもの（例: Rtools44）をダウンロード。
  2. インストール時のオプションで “Add rtools to system PATH” に必ずチェックを入れる。

8.5 VS Code & Quarto の導入

8.5.1 VS Code 本体と拡張機能

  1. VS Code 公式 からインストール。
  2. 左側の「拡張機能 (Extensions)」から以下をインストール。
    • Japanese Language Pack: 日本語化。
    • Quarto: 執筆・プレビュー用。
    • R (Publisher: REditorSupport): コード補完・実行用。
    • Markdown Preview Mermaid Support: フローチャート用。
    • Git Graph: コミット履歴の可視化。

8.5.2 Quarto CLI (Command Line Interface)

  1. Quarto Get Started から Windows 用 .msi をダウンロード・インストール。
  2. 重要: インストール後、パス反映のため VS Code を再起動する。

8.6 Git と GitHub のセットアップ

8.6.1 アカウントとインストール

  1. GitHub でアカウント作成（学生は大学メアド推奨）。
  2. Git for Windows をインストール（デフォルト設定でOK）。

8.6.2 ユーザー設定と認証

VS Code のターミナルで以下を実行。

git config --global user.name "Taro Tanaka"
git config --global user.email "taro.tanaka@univ.ac.jp"

その後、VS Code の「ソース管理」アイコンから GitHub にサインインする。

8.6.3 GitHub Education (Copilot 無料化)

博士課程学生は GitHub Copilot を無料で利用できる。 * 1. GitHub Education から学生証をアップロードして申請。 * 2. 承認後、VS Code に拡張機能 “GitHub Copilot” を入れ、サインインする。

8.7 【重要】セキュリティ対策 (.gitignore)

研究データ（特に PMS データや患者リスト）は、絶対に GitHub 上に公開してはならない。 Git の管理対象から除外する設定ファイル .gitignore を必ず設定する。

8.7.1 .gitignore の設定手順

プロジェクトフォルダの直下に .gitignore という名前のファイル（拡張子なし）を作成し、以下を記述する。

# R 関連のシステムファイル
.Rproj.user
.Rhistory
.RData

8.8 VS Code の最適化設定 (settings.json)

R をスムーズに動かすための設定。Ctrl + , → 右上のアイコン（JSONを開く）で以下を追記する。

{
    "r.rpath.windows": "C:\\Program Files\\R\\R-4.4.2\\bin\\x64\\R.exe",
    "r.plot.view": "httpgd",
    "editor.bracketPairColorization.enabled": true,
    "r.alwaysUseActiveTerminal": true,
    "r.sessionWatcher": true
}

※ httpgd を使う場合は install.packages("httpgd") が必要。

8.9 文書の出力 (Word, PDF, HTML)

Quarto は、1つの .qmd ファイルから多様な形式に出力できる。

8.9.1 準備：PDF エンジンのインストール

PDF 出力には LaTeX 環境が必要だが、Quarto 専用の軽量版 TinyTeX を使うのが最も簡単である。 ターミナルで以下を1回実行する。

quarto install tinytex

8.9.2 出力形式の指定 (YAMLヘッダー)

.qmd ファイル冒頭を以下のように記述することで、形式を切り替えられる。

---
title: "研究計画書"
format:
  html:
    toc: true       # 普段のプレビュー用
  docx:
    toc: true       # 指導教官への提出用（Word）
  pdf:
    documentclass: scrartcl # PDF出力用
---

8.9.3 出力実行 (Render)

  1. コマンドパレット: Ctrl + Shift + P → Quarto: Render を選択。
  2. 形式選択: docx, pdf, html から選択する。
  3. 数秒〜数十秒でファイルが生成され、自動で開かれる。

9 トラブルシューティング

9.1 Mermaid 関連

9.1.1 Mermaid の図が表示されない

  • VS Code は記法に厳格である。
    • バッククォート ``` は必ず左端に寄せる（インデント禁止）。
    • %%{init: ...}%% 内は必ずダブルクォート " を使う。
    • YAMLヘッダーのcssオプションが悪さをしている場合があるので、コメントアウトして動作確認する。
    • 中黒（・）や全角スペースが混入していないか確認する。

9.1.2 Mermaid 図をクリックで拡大したい

Lightbox 拡張機能をインストールし、YAMLヘッダーに以下を追加する。

format:   
  html:
    lightbox: true

9.2 パッケージが見つからない (not available)

開発版 R (x.x.0) を使用時、CRAN にバイナリがない場合がある。 remotes パッケージを使い GitHub からインストールする。

install.packages("remotes")
remotes::install_github("nx10/httpgd")

本マニュアルを遵守し、安全かつ効率的な研究ライフを。

10 Appendix: GitHub Pages Deployment

作成したハンドブックや研究ポートフォリオを、Webサイトとして公開し、URL一つで共有するための手順。

10.1 準備 (Best Practice)

Webサーバーの仕様上、トップページにしたいファイル名は index.html にするのが標準である。

  1. Rename: メインの .qmd ファイルの名前を index.qmd に変更する。
  2. Render: 再度Renderを行い、index.html を生成する。
  3. Push: VSCodeからGitでCommit & Pushを行う。

10.2 GitHub設定

  1. ブラウザでGitHubのリポジトリページを開く。
  2. 上部タブ [Settings] > 左サイドバー [Pages] をクリック。
  3. Build and deployment セクションにて：
    • Source: Deploy from a branch を選択。
    • Branch: main (または master) を選択。
    • Folder: / (root) を選択。
  4. [Save] ボタンをクリックする。

10.3 アクセスと共有

設定から1〜2分後、ページ上部にURLが表示される。

  • URL形式: https://[ユーザー名].github.io/[リポジトリ名]/
  • 共有: このURLをLINEやSlack等で共有すれば、PC・スマホ問わず閲覧可能となる。
Important⚠️ 公開設定の注意

GitHub Pages（無料版）を使用する場合、リポジトリの設定を Public（全世界公開） にする必要がある。 公開する前に、「個人情報」「未発表の研究データ」「緊急用パスワード」などがリポジトリ内に含まれていないか、再度確認すること。
